# Settings, keybindings, and themes

Global `settings.jsonc`, `keybindings.jsonc`, theme files, and Main-owned boot `argv.jsonc` live in the application data directory. Writes sync a mode-`0600` temporary file before atomic replacement, and in-memory state changes only after replacement succeeds. The Server Core prefers Parcel Watcher hot reload and falls back to polling only the three runtime configuration files. The Settings service and Main-owned argv path share a 256 KiB UTF-8 source ceiling; argv's synchronous pre-ready read and asynchronous read/update path open a descriptor, require a regular file, read through limit plus one byte before parsing, and use `O_NONBLOCK` so a FIFO cannot hang the Desktop. Missing or invalid argv source keeps the existing defaults/template behavior; oversized or non-regular argv targets fail closed and are never replaced. Schema or size errors retain defaults or the prior valid state and report location without including source text in diagnostics. Missing provider-scoped Agent launch, disabled-by-default lifecycle-hook and output-recovery settings, and the nullable Terminal default cwd are supplied in memory without rewriting an older settings file. Each Agent provider's lifecycle integration can be enabled independently; installation health is a separate typed read/event surface because a saved preference does not prove that a provider loaded or trusted its hook. Provider recovery settings bound user pattern count and length plus both input delays; diagnostic exports retain only enablement, delay values, and the user-authored pattern count. Trusted Domains are a bounded Settings array of normalized HTTP(S) exact origins or explicit subdomain wildcard origins. Server Core owns their JSONC-preserving atomic persistence, while Main alone may append the canonical exact origin selected in a trust prompt; Renderer can manage the complete array only through the ordinary validated Settings update. Trusted Folders follow the same shape for absolute POSIX directory paths: Main alone may append the parent folder confirmed in a Terminal external-link prompt, and a matching folder only skips that prompt for later read-only opens. Object-valued `files.exclude` merges user booleans over bounded defaults, so a default pattern can be disabled with `false` without re-declaring every other default.

The Settings dialog opens in full-width structured UI mode. Its in-app source mode lazily mounts Monaco against the same reducer drafts. Invalid source shows a readable parse error with Go to line and Revert changes actions; leaving Source discards the invalid draft. Server and Renderer import the same browser-safe Settings and keybinding schemas from `packages/protocol/src/configuration`, so defaults, bounds, and source-to-UI validation cannot drift. Hook installation health describes the last applied settings only: an edited toggle reports `Pending Apply`, and the provider section tells users that Agent Terminals opened before enablement need a restart. View switching is a two-segment UI/Source toggle; the former external `Open Config File` action was removed because macOS has no default `.jsonc` association and the in-app source editor owns config editing.

A keybinding's `key` holds one or two whitespace-separated chords (`cmd+k cmd+s`), normalized and capped by `packages/protocol/src/configuration/shortcuts.ts`. A chord that opens a sequence (every leading chord in the live table, plus the unconditionally reserved `cmd+k`) arms the Renderer's pending chord instead of dispatching, so a single-chord binding on it can never fire; `findKeybindingConflicts` reports that overlap and `reconcileDefaultKeybindings` treats the chord as occupied. Ownership of a sequence is decided at its leading chord: with Monaco focused the whole sequence belongs to the editor's independent resolver and Caxri stands down. Full model in [docs/keybindings.md](../../../../docs/keybindings.md).

Themes normalize into one semantic token structure consumed by CSS variables, xterm, and Monaco. Dracula is vendored as the first-run default. Importers support Caxri JSON, one VS Code JSON theme, iTerm2 `.itermcolors` plist, and Warp YAML; missing non-terminal tokens inherit from the active theme. `themeTokensSchema` owns only saved colors and metadata. `theme.importPath` returns `{ value, warnings }`, where each transient warning has a stable `id` and a display `message`; `theme.get` and `theme.json` never contain warnings. Renderer holds warnings for the current imported theme in its Settings reducer and keys dismissals by warning id. A new import resets dismissals, while a fresh load after restart has no import warnings. A contrast rejection carries the failing color roles and measured ratio in structured error details so the dialog can name the color to change.
