# Caxri architecture

## Product model

A `Project` is a user-selected local folder and the durable owner of its `rootPath`, explicit Sidebar order, file tree, Git context, and path-security grant. A `Session` belongs to one Project and owns permanent Terminal records, editor/layout state, and optional Agent metadata. Archiving a Session hides it from active navigation without stopping or deleting its Terminals, and restore only clears that metadata. The first Agent Terminal in a Session is its automatic title source; a user rename switches the title to manual ownership so later Agent metadata cannot replace it. Shell-only Sessions keep their Shell title. Multiple Sessions can share one Project without duplicating its directory identity.

## Process model

```text
Electron Main
  -> secure BrowserWindow + native dialogs
  -> dedicated Process Explorer window + fixed process sampler
  -> correlated IPC allowlist
  -> utilityProcess Runtime supervisor

Preload
  -> typed request/event bridge only

Renderer
  -> React, xterm.js, Monaco, shadcn/ui on Base UI
  -> separate Process Explorer entry with a snapshot-only preload

Runtime utilityProcess
  -> Project/Session/PTY/File/Git/Agent/Settings/Theme/Diagnostics services
  -> better-sqlite3 through Drizzle ORM
```

The Renderer never owns runtime truth. A renderer reload attaches to the existing Runtime and receives current metadata plus bounded snapshots. A Runtime crash invalidates every in-memory PTY; the supervisor restarts with capped exponential backoff and persisted terminals are exposed as `dead`, never as silently restored processes. A Runtime must remain ready for 30 seconds before its restart budget resets, so ready/crash flapping still fails closed after three restarts.

The Process Explorer is a singleton Main-owned window with its own renderer entry and narrow preload. While open, it samples a fixed `/bin/ps` argv every two seconds, filters the result to descendants of the Caxri Main process, overlays Electron process metrics, and exposes only process name, parent/PID, CPU, and resident memory. Common credential flags are redacted before the snapshot crosses IPC. It cannot access the workbench request bridge, Terminal output, environment values, source files, or Agent transcripts; closing it never changes Runtime or PTY lifecycle.

## IPC contract

Renderer requests use `{ id, method, params }`; Runtime replies use `{ id, ok, result | error }`; runtime events use `{ event, payload }`. `src/shared/ipc` holds one method table that pairs every method name with its owner (`main` or `runtime`), a Zod params schema, and a Zod result schema; domain types, the runtime event union, and the terminal split layout are Zod schemas in the same module, so both processes and the Renderer infer their types from a single declaration. Internal methods live in a separate table that the Renderer envelope rejects. Zod validates all renderer request parameters before forwarding. Main keeps a pending request table with timeouts and request correlation IDs. Runtime output events are batched and bounded before crossing process boundaries. Structural state changes request the full bootstrap convergence snapshot; steady-state Terminal and Agent metadata events carry typed Session/Terminal identities and use the bounded `app.records` read so they never resend the whole application graph. An unrecognized state-change scope normalizes to the full convergence path.

The Runtime resolves that table through one composition root. `createRuntime(deps)` constructs and wires every service from injected dependencies (data directory, logger, event sink, and PTY/Agent seams) and returns an exhaustive handler table plus a single disposal path, so the entry point only connects the parent port and the whole request surface is exercisable in-process without Electron. One dispatcher validates each request, invokes its handler, records the request boundary, and classifies failures.

Runtime module placement follows one scale rule: a domain may remain flat while it has at most two production modules; at three or more cohesive modules it owns `src/runtime/<domain>/`, exposes its boundary through `index.ts`, and keeps its tests in that directory's `__tests__/`. Git, Terminal, Agents, Files, and DB use this nested shape. Cross-domain Runtime imports stay relative.

Failures carry a closed error code (`VALIDATION`, `NOT_FOUND`, `PATH_DENIED`, `CAPACITY`, `UNAVAILABLE`, `TIMEOUT`, `CONFLICT`, `IO`, `GIT`, `INTERNAL`). Runtime and Main encode a `CaxriError` into the wire reply, and the supervisor and preload rebuild it on the other side, so a code survives every process hop instead of degrading into an opaque message. Unrecognized codes decay to `INTERNAL`, and only `INTERNAL` failures log a stack.

The preload exposes one `request` method backed by a fixed method union plus `onEvent`. It does not expose `ipcRenderer`, Electron objects, environment data, or generic filesystem/process access. Main starts the Runtime with an allowlisted environment containing only process-launch context, tool state locations, and Caxri-owned paths; ambient credential variables are not copied into the utility process.

## Persistence

SQLite runs only in the Runtime and uses WAL, foreign keys, transactions, and busy timeout. Table definitions live declaratively in `src/runtime/db/schema.ts` (Drizzle ORM); `bunx drizzle-kit generate` emits the checked-in SQL under `src/runtime/db/migrations/`, which the Runtime bundles via `?raw` imports so packaged builds never read migration files from disk. After any schema change, regenerate with drizzle-kit — never hand-edit the migrations directory. `user_version` is currently 9. Schema 7 is the incremental-migration preservation floor: older experimental databases may still be rebuilt, but schema 7 and every later version advance transactionally without deleting Projects, Sessions, Terminals, snapshots, selection, or layout state. Caxri's public data-compatibility commitment begins with v1.0.0, backed by that preserved chain; adding a schema version requires both generated SQL and an N-1 upgrade test. Query modules use the Drizzle query builder while the raw better-sqlite3 handle remains for pragmas and transactions. The schema contains:

- `projects`: identity, unique root, display title, explicit Sidebar order, and timestamps
- `sessions`: Project ownership, identity, timestamps, reversible archive time, primary Agent Terminal, last activity, layout version, and automatic/manual title ownership
- `terminals`: durable identity/position/cwd/title/icon/provider and last process state
- `terminal_snapshots`: versioned bounded VT/text payload with line and byte counts
- `session_state`: versioned open editor tabs, active tab, inspector mode, and a recursive Terminal split layout; invalid JSON, invalid shapes, or unsupported versions repair to a default layout and emit a content-free warning instead of failing bootstrap
- `app_state`: last selected Project and Session, window state, active theme, and schema version

Snapshots retain at most 2,000 lines and 2 MiB per Terminal. Output is appended to chunk buffers and compacted on a debounce so the PTY data callback neither rescans the full snapshot nor writes SQLite. A Renderer subscribes before attaching, then replays the bounded snapshot ahead of output received during attachment. Bytes already represented by that snapshot are removed from the live-output queue before replay to prevent duplication. Detached Terminals retain bounded snapshots without broadcasting output to an invisible view. Snapshots are UI restoration data, not proof that a process survived.

## PTY lifecycle and backpressure

Runtime launches only discovered allowlisted programs (`$SHELL` or a registered Agent provider) with structured argv, a persisted cwd, and a filtered environment. Each provider owns bounded launch executable/argument settings; configured initial args precede provider-owned resume args. Agent executables use a cached, bounded login-shell PATH shared with version probes, while normal Shell Terminals retain their existing login-shell startup. Standard proxy and custom-CA variables are retained, while unrelated credentials and Caxri-internal variables are excluded. A new Terminal resolves the global default cwd (`~` supported) or falls back to its Project root before its durable record is inserted; restarts always reuse that record, and Files/Git authorization remains anchored to the Project root. Switching Sessions detaches views but does not stop PTYs. Renderer output delivery is coalesced; per-terminal queues have a byte ceiling and emit a dropped-output marker when the renderer cannot keep up. Durable Terminal creation is capped at 16 per Session and 32 globally. The Renderer bundles JetBrains Mono's four terminal faces plus Symbols Nerd Font Mono as a fallback and loads them before xterm measures its cells, so packaged builds do not depend on system-installed terminal fonts.

Terminal groups form a persisted binary split tree with horizontal or vertical direction and a bounded ratio. Dragging a tab moves its durable Terminal ID between groups or creates a new split; shared reducers collapse empty groups and validate that one Terminal cannot appear twice. Moving a view may detach and reattach xterm, but the Runtime-owned PTY is neither restarted nor duplicated. Keyboard-adjustable separators and group labels preserve accessible focus semantics.

The active Terminal's Status Bar metrics remain Runtime-owned. A fixed `ps` argv samples only PID, PPID, and RSS for the live PTY process tree every two seconds while that Terminal is visible; the Renderer receives aggregate memory and descendant count, never commands or environment data. Sampling stops when a file tab is active and an exited PTY returns no usage.

Default `Command+K`, `Command+T`, and `Command+W` bindings clear the active xterm view, create a Terminal in the active group, and close the active Terminal through its normal lifecycle. Clear is Renderer-local and never sends input or a signal to the PTY. All bindings remain configurable, and app-wide commands are ignored while a modal dialog is open. Command-backed native menu items derive placement, ordering, labels, and accelerators from the shared command catalog and live keybindings; only standard Electron role items stay explicit in Main. Inspector modes register their schema value, show command, catalog metadata, and default binding once in `src/shared/inspector.ts`; the Renderer panel map remains exhaustive and type-checks each mode against its derived command id.

Closing the last macOS window with live PTYs asks whether to keep running, terminate and close, or cancel. `Keep Running` detaches every Renderer view and closes the window while Main, Runtime, and PTYs remain alive; reopening creates a new window and attaches it to the live Runtime. Explicit App Quit terminates PTYs and waits briefly for ordered Runtime shutdown. Persisted processes are marked stopped after a normal quit. Dead terminals remain visible and can be restarted. In-flight Agent CLI discovery is revalidated against durable metadata before a PTY is registered, so closing a Terminal or deleting its Session cannot create an orphan process.

Interrupted-Terminal recovery is supervised by one Runtime-wide four-spawn budget. Selecting a Session invalidates queued restore work from the previous selection, and the selected generation is revalidated after executable discovery immediately before PTY spawn. Startup Agent metadata probes are limited to the selected Session; another Session is probed when selected rather than during boot.

Exited Terminals retain their final output and reserve a compact recovery row beneath the xterm viewport, never over it. A zero exit without a signal is neutral; startup failures and signal or non-zero exits use a danger state. Surface actions, the command palette, and `Command+Shift+R` restart the same durable Terminal record, so recovery cannot create a duplicate tab or PTY identity.

## Files and editor

The Files inspector resolves a curated, deterministic subset of local LobeHub file icons by exact filename, well-known directory, test suffix, and extension before falling back to generic file and folder assets. Expanded directories use matching open variants. Vite emits only the explicitly imported SVG subset as separate assets, so icons remain offline-capable without embedding the full upstream catalog in the initial Renderer JavaScript bundle.

Agent identity is a Renderer-wide typed registry rather than a per-surface icon choice. Terminal tabs, Project Session rows, creation choices, Terminal Info cards, and Settings resolve the same Claude Code, Codex, Shell, reserved Grok/OpenCode, or unknown identity. Brand SVGs are emitted as local build assets; monochrome icons inherit the active theme, and unsupported future adapters use a deliberate generic fallback. The Info inspector lists only Terminals owned by the selected Session, including their process state, PID when live, directory, and correlated Agent session ID; installed tools that were not started in that Session never appear there.

Every file request resolves its candidate path, obtains the authoritative root from the Session's Project, checks the candidate remains beneath that resolved Project root, rejects symlink escapes, and enforces text/size limits. Saves open the validated inode with `O_NOFOLLOW` before truncation. Directory identity is revalidated around enumeration so a path swap cannot disclose another directory, and entry metadata reads use a bounded worker pool. Directories are lazy-loaded. File-tree visibility follows the global VS Code-style `files.exclude` glob object and never reads `.gitignore`; dependency and build directories remain visible by default. `@parcel/watcher` uses the native recursive macOS backend, independently ignores VCS internals and dependency/build caches, coalesces bursts, and watches the active root only. Polling is inactive while that backend is healthy; a bounded fallback starts only after native setup or delivery fails and polls the active root plus expanded directories that are not excluded by the watcher traversal policy. A normal watcher batch reloads only the directory that directly owns a changed path, while overflow reloads all visible directories and switching Session identity intentionally resets expanded absolute paths.

Project search is a Session-scoped Runtime read, never a Renderer-supplied root or command. Name and content scans use an independent bounded traversal policy for VCS metadata, dependencies, and build caches rather than `files.exclude`; they revalidate directory/root identity, reject symlinks, skip binary and oversized documents, and cap time, scanned files, matches, snippets, and total IPC payload. A newer search aborts the prior scan for that Session; the Renderer also keys results by the complete query so a stale response cannot replace a newer query. Content options cover case, whole word, regular expression, include, and exclude matching, while Monaco reveal intents remain keyed by the Session-specific model URI.

External disk changes always replace an open buffer, including a dirty buffer. This is a deliberate product choice for agent-driven workflows; the Renderer clears dirty state and shows a non-blocking notice rather than opening a conflict dialog. Editor buffers and Monaco model URIs are keyed by Session identity as well as path so Sessions sharing one root cannot reuse each other's dirty state. Clean document contents share a 32 MiB Renderer cache budget across Sessions; dirty buffers are the only exception because reclaiming them would lose unsaved work, and they displace clean buffers first. Closed models do not retain Monaco view state. When a Session becomes active again, cached documents are compared with current disk version metadata; only actual disk changes replace its inactive dirty buffers.

Git file selections open read-only virtual editor tabs instead of embedding patch text in the Inspector. A single-file tab renders a Monaco side-by-side diff; a repository `Open Changes` tab renders its changed files as one scrollable multi-diff surface. Multi-diff rows load their bounded document and mount Monaco only near the viewport; a binary or transient per-file failure remains local to that row. The virtual tab key persists the opaque repository ID and repository-relative path so reload can reconstruct the diff without treating it as a writable filesystem document.

For a normal active file tab, Monaco publishes only cursor, selection length, and language identity to Renderer-local Status Bar state. Current-line blame is a bounded, Session-rooted Runtime Git request that selects the deepest approved repository containing the file and returns commit metadata only; diff tabs never masquerade as writable files or issue blame requests.

## Settings, keybindings, and themes

Global `settings.jsonc`, `keybindings.jsonc`, and theme files live in the application data directory. Writes sync a mode-`0600` temporary file before atomic replacement, and in-memory state changes only after replacement succeeds. The Runtime prefers Parcel Watcher hot reload and falls back to polling only these three bounded files. Startup and hot-reload changes are schema-validated before replacing in-memory state; parse errors retain defaults or the prior valid state and report location without including source text in diagnostics. Missing provider-scoped Agent launch settings and the nullable Terminal default cwd are supplied in memory without rewriting an older settings file. Object-valued `files.exclude` merges user booleans over bounded defaults, so a default pattern can be disabled with `false` without re-declaring every other default.

Themes normalize into one semantic token structure consumed by CSS variables, xterm, and Monaco. Dracula is vendored as the first-run default. Importers support Caxri JSON, one VS Code JSON theme, iTerm2 `.itermcolors` plist, and Warp YAML; unsupported tokens become warnings and missing non-terminal tokens inherit from the active theme.

## Git and Agent adapters

Git operations run via `execFile('git', argv)` with fixed argv constructors and a filtered environment. The only repository mutation exposed to the Renderer is switching to an existing local branch: Runtime resolves the opaque approved repository ID, re-lists its bounded local refs, and invokes `git switch -- <branch>` only after an exact match. There is no arbitrary checkout, fetch, reset, discard, or command surface. One Runtime-wide semaphore admits at most eight Git subprocesses, metadata commands cap output at 4 MiB, and bounded file-diff commands retain the configured file-size cap. A shared Runtime resolver checks the GUI PATH, then reads only a bounded marker-prefixed PATH from the login shell; it caches validated absolute executables and revalidates stale entries. Agent adapters, Agent PTYs, version probes, and the fixed Project Status allowlist (`gh`, `vc`, `linear`) use this resolver and its filtered environment without inheriting the rest of the shell environment. Claude Code integration reads only compact live-session metadata: at most 512 candidates, eight reads at once, and no more than 128 KiB from any file. Codex integration locates state beneath the documented `CODEX_HOME`/`CODEX_SQLITE_HOME` roots and queries a capability-detected thread index read-only; neither adapter opens transcripts. Available title, session ID, activity, and usage metadata are correlated with the persisted cwd of the matching provider Terminal. A provider-owned Agent session ID may be claimed by only one Terminal; unbound probes exclude IDs already claimed by another Terminal and IDs discarded by a restart. The first Agent Terminal becomes the Session's primary Agent Terminal and exclusively owns an automatic sidebar title; later Agent Terminals retain independent metadata without replacing it. A manual title remains stable across Agent metadata refresh, restart, and primary-Terminal succession. Closing the primary promotes the next Agent Terminal. Missing or changed storage produces `unknown`; it never interrupts PTY input/output or resets a known Session title.

A Shell Terminal can become an Agent Terminal when its unpublished input line launches `claude` or `codex`, either directly or through a shell alias. Runtime keeps a simple-command candidate in memory for a bounded window and confirms aliases from the PTY's active foreground process group using a fixed, bounded `ps` query; compound commands and background processes are excluded. Once the provider executable is confirmed, Runtime promotes the durable Terminal atomically so its shared icon and title update even before the provider writes session metadata. A later same-Project, unclaimed metadata session created after command submission supplies the Agent session ID and generated title. Shell input and process-list output are never logged or persisted, and ordinary output alone does not infer Agent identity.

The Git inspector treats the selected Project repository, linked worktrees, nested repositories, and initialized submodules as independent status scopes. Its Working Tree mode uses the current index and filesystem, while its lazy Pull Request mode asks `gh pr view` for the current branch's validated base/head object IDs and diffs that committed range without mixing in local working-tree changes. Repository discovery uses structured Git output, coalesces concurrent summaries, and passes an opaque repository ID back for diff requests. `git.diffDocument` returns bounded original and working-tree text for Monaco without exposing an arbitrary Git command or weakening repository containment. Nested roots inherit the containing Project grant. A linked worktree outside that root appears only after its directory has independently been added as a Project; Git discovery never expands durable path authority.

Each approved Git scope also exposes lazy, independently pageable commit history through its opaque repository ID. Runtime parses fixed NUL-delimited `git log` fields, caps page size and offset, and accepts only an existing, non-symlink path contained by that repository for optional subtree history. Selecting a commit issues a separate read-only metadata/file-list request; merge commits compare through their first-parent history, file results are bounded, and no history request exposes checkout, reset, fetch, or another mutation.

The Project Status inspector is lazy: opening its tab asks Runtime to combine the approved primary repository and initialized submodules with GitHub PR/check data, deliberate Linear references from the PR body, and Vercel deployments. The always-visible Status Bar uses a separate lightweight primary-repository overview: it reads Git changes plus the origin and current GitHub PR, never triggering Linear or Vercel, and file events refresh only `git.summary`. Its branch picker lazily lists the approved primary repository's local refs and uses the narrow switch operation above; its additions/deletions are the tracked working-tree diff against `HEAD`, while untracked files remain visible in Source Control without synthetic line counts. Runtime invokes `gh`, `linear`, and `vc` only through structured argv arrays, filtered environment inheritance, timeouts, and bounded output; Renderer receives validated read models and never CLI access. Missing tools, authentication, links, rate limits, and timeouts stay scoped to the relevant surface, while external HTTP(S) links still pass through Main's confirmation boundary.

## Security

BrowserWindows use `contextIsolation: true`, `nodeIntegration: false`, sandboxed renderers, a restrictive CSP, blocked navigation, and denied new windows. External HTTP(S) URLs require explicit user intent before Main uses the system browser. No telemetry or remote upload exists.

Directory-picker results create single-use Main-process grants. A grant is revoked when the Agent choice is canceled, expires after 60 seconds if unused, and is consumed before Project creation reaches the Runtime. Once a Project exists, new Sessions reference its stable ID and cannot submit or broaden a root path.

## Performance and observability

Main and Runtime record boundary timings for app readiness, Runtime attachment, first window visibility, Runtime boot, PTY spawn, file listing, Git commands, Agent probes, and watcher readiness. Concurrent identical file, Git, Agent, and Terminal-start requests share one in-flight operation so development StrictMode and repeated UI requests do not duplicate native work. Agent Terminal output schedules a trailing metadata refresh with at most one timer per Terminal, allowing a CLI-generated title to reach the sidebar without opening the Info inspector. One Agent coordinator owns that scheduling and reads Agent Terminal membership from the durable Terminal record instead of a cached set, so no lifecycle path can leave the two disagreeing. Ordinary Shell and dev-server output never enters this probe path; only a bounded simple-command candidate may request coalesced foreground-process confirmation, after which normal Agent metadata refreshes take over.

Terminal input, resize, and output are high-frequency paths. Successful input and resize requests do not write individual records, repeated ResizeObserver grid sizes do not cross IPC, and Runtime ignores a resize that matches the live PTY grid so a remounted view cannot generate a redundant SIGWINCH. PTY throughput is emitted as periodic aggregate input, output, and dropped-byte counters. Recovery snapshots retain bounded output in incrementally trimmed chunks and persist changed state at most once every five seconds, plus the final exit/restart snapshot, rather than rebuilding and rewriting a full BLOB every 750 ms. Bootstrap loads all Session state rows in one query. Terminal exit, restart/restore, and Agent metadata events refresh only their identified records through one coalesced small read; application attach, Runtime recovery, and structural mutations retain full bootstrap as the convergence path. Monaco stays out of the terminal-first Renderer bundle; after Runtime attachment, a single shared idle preload primes editor-core plus JavaScript, TypeScript/TSX, JSON, HTML, CSS, Markdown, and dotenv tokenization before the first real file selection. Language workers remain demand-loaded.

`benchmark:startup` exercises a representative large repository and requires Runtime, Terminal, Files, and Git to become usable within three seconds. It also validates timed log coverage, zero request/watcher failures, aggregated terminal metrics, and fewer than 256 Runtime file descriptors. `benchmark:editor` separately launches isolated cold and idle-preloaded renderers. The common-language idle preload must complete within three seconds; the first JavaScript or TypeScript document, editor mount, and visible syntax highlight must complete within 250 ms of selection in both paths, and a repeated open must visibly highlight within the same bound.

## Diagnostics and privacy

Structured logs carry timestamp, process, level, event, correlation ID, duration, and the build's application version and commit when known. Diagnostics contain application/runtime versions, redacted metadata/state, counts, and timing summaries. Home paths normalize to `$HOME`; secret-like keys, bearer/API tokens, GitHub tokens, and Slack tokens are redacted. Bundles never include file contents, terminal output/snapshots, environment values, prompts/responses, or agent transcripts.

The application version and short commit hash are injected at build time and read once by Main, which stamps its own logs and forwards them to the Runtime's environment so both processes' logs and the diagnostics export can be correlated to the exact build.

Development launches write Main and Runtime JSONL files to the repository `logs/` directory for direct inspection. Packaged and test launches keep logs beneath the active Electron user-data directory so application data remains self-contained.

## Recovery limits

Renderer reload recovers UI state and attaches to live PTYs. Runtime restart recovers database metadata and snapshots only; operating-system PTYs owned by the dead Runtime are not recoverable. Restart attempts are capped and use exponential backoff; a Renderer request that arrives while a crash-triggered restart is waiting out its backoff delay is queued to await that same restart rather than forking early. Startup fails visibly instead of hanging if no Runtime becomes ready within 15 seconds. App exit is the only supported durable process boundary; PTYs do not outlive an explicit quit.

A Renderer process crash (`render-process-gone`) reloads the window automatically with backoff (250ms, then 1s, then 4s). After three crashes within a 60-second window, automatic reload stops; Main logs the crash loop and shows a native dialog offering Relaunch or Quit instead of reloading indefinitely.
