# Filesystem authority, links, and mutations

File explorer, path-browser, and editor navigation trust links reached through the Session's Project root, including external targets. File reads, saves, listings, and open authorization keep the normalized workspace entry as the document identity while using the canonical target for filesystem operations and operation-queue ordering. Direct outside paths remain unauthorized. Saves preserve the workspace link and validate temporary files against the canonical target directory. Other filesystem operations retain canonical Project containment and their existing mutation restrictions; replaced Project roots and text/size violations remain rejected. Saves hold the validated inode open with `O_NOFOLLOW`, write and sync a same-directory temporary file, revalidate the target identity, then atomically rename the complete replacement over it and sync the directory; an interrupted save therefore leaves either the old full bytes or the new full bytes. Following VS Code's local disk-provider boundary, create, recursive copy, rename, and move use asynchronous Node filesystem APIs inside Server Core. Server Core coordinates document reads, saves, and mutations through one bounded path-aware scheduler: overlapping paths remain ordered, unrelated files continue during long operations, and recursive copies are serialized per Project. A document request that waits too long is canceled inside that scheduler before its filesystem operation starts; Main therefore leaves saves pending for Server Core's authoritative result instead of reporting a timeout while a write can still execute. Server Core revalidates source and target identities before mutation, rejects root changes, symlinks, hard-linked regular files, conflicts, and directories copied or moved into themselves, and reserves target paths so concurrent Caxri requests cannot select the same name. Recursive copies preflight a bounded manifest for entry count and aggregate bytes, then use abortable Node file-handle streams so the operation deadline covers active transfer. A failed copy preserves its partial target because Node cannot atomically bind pathname deletion to a validated inode; structured failure records report the safe aggregate counts, duration, and operation phase without risking deletion of a foreign replacement. Source entries, destination directories, and created parent directories are revalidated throughout the copy. Path-based rename performs a final conflict check and Caxri-local reservation; Node has no atomic no-replace directory rename API, so an external process can still win the final path race. Keeping these narrow VS Code-aligned pathname limitations is an explicit tradeoff of the Node-only implementation. Cut/copy state is Renderer-local metadata naming the item's path and the Session it was cut or copied in, so a paste may land in another Project: `files.copy` and `files.move` then carry `source: { kind: 'session', sessionId }`, and Server Core authorizes the source against that Session's root and the target against the pasting Session's root, on every paste. Copy-in from Finder (a drop on the tree, or Cmd+V of files Finder copied, read through Main's local-only `clipboard.readFilePaths`) is the one unrooted source: `files.copy` with `source: { kind: 'external' }` takes an absolute regular file or directory chosen by the user, rejects symlinks and hard-linked files, only reads it, and still confines the target to the pasting Session's root; an SSH Host window refuses it because those paths name files on this Mac. A cross-device move fails with an explicit error rather than a copy-and-delete fallback. Copy/duplicate and cut-paste choose a bounded collision-free suffix. The Renderer coalesces repeated long copy or move intents, exposes an accessible pending status, disables duplicate triggers until completion, and reports failures; a completed create, copy, rename, move, Trash, or Trash undo shows in the tree itself and raises no toast, except a Trash that discarded unsaved edits. Main reveals an item in Finder only after Server Core authorizes the current Project-local regular file or directory. `Open in Terminal` supplies an optional cwd to `terminal.create`; Server Core canonicalizes it, requires a directory beneath that Session's Project root, captures its inode, and revalidates that identity in `TerminalManager` immediately before each path-based node-pty spawn, including restart and restore. A final check-to-spawn race remains because node-pty accepts only a cwd pathname; this is the same explicit Node-only local-filesystem tradeoff, not a descriptor-backed sandbox boundary. For Trash, Main shows the native recovery warning, repeats Server Core inode and Project-root authorization after confirmation, and then calls Electron's path-based `shell.trashItem`; there is no permanent-delete fallback. Successful mutations invalidate affected file-tree queries for every Session sharing the Project. Successful renames and moves also remap normal editor tabs, independent dirty buffers, and in-flight reads or writes for the item and its descendants across those Sessions; successful Trash operations close affected tabs and discard pending document completion across the same scope. Directory identity is revalidated around enumeration so a path swap cannot disclose another directory, and entry metadata reads use a bounded worker pool. Directories are lazy-loaded. Identical concurrent directory reads share one bounded Server Core producer; cancellation stops only that caller's wait and never aborts another caller that joined the same read. The `Cmd+P` path browser uses a separate bounded `files.browse` request to scan only its current Project-local directory; navigation cancels stale Session scans and active scans share a small Server Core-wide concurrency budget. Only when a typed relative directory does not exist does Main fall back once to `files.locateDirectory`, the same bounded, exclusion-aware suffix traversal Terminal link resolution uses; Server Core picks the shallowest matching Project directory and Main lists it after revalidating that it is still inside the Project root; ordinary browsing never triggers a Project-wide traversal. Browse describes regular entries from the opened directory handle's metadata alone, while tree listings still stat each entry for its size; a symlink entry in either listing is the one deliberate relaxation, receiving a single type-only follow through the listing's shared timeout budget so the row can show a folder or file icon (the same follow VS Code's disk provider takes), while opening and expanding trusted workspace links are separate requests that resolve the current target; link-entry copy, move, rename, and Trash retain their existing restrictions. File-tree visibility follows the global VS Code-style `files.exclude` glob object and never reads `.gitignore`; dependency and build directories remain visible by default. `@parcel/watcher` uses the native recursive macOS backend, independently ignores VCS internals and dependency/build caches, coalesces bursts, and watches the active root only. Polling is inactive while that backend is healthy; a bounded fallback starts only after native setup or delivery fails and polls the active root plus expanded directories that are not excluded by the watcher traversal policy. A normal watcher batch reloads only the directory that directly owns a changed path, while overflow reloads all visible directories and switching Session identity intentionally resets expanded absolute paths. Native watcher subscriptions still cover the Project root only; changes made externally to out-of-root link targets are reported by the separate external-link observer described below rather than by native Project file events.

The Project-local description above is the anchored `Cmd+P` mode. Backspace or Delete at the start of
its empty input removes the Project anchor and enables the local Desktop's explicit-path mode. That mode
accepts current-user `~`, parent and relative paths, and `/`-rooted absolute paths, then lists matching
folders and files without a native picker. Main resolves the user-entered path, bounds concurrent
enumeration and entry count, keeps canonical locations and candidates behind opaque browser and entry
IDs, revalidates directory and file identity, rejects symbolic-link traversal, and reads only bounded
regular text files through a no-follow descriptor. Free-path browsing has no create authority. A result
inside the current Project returns through the existing authorized editable Editor path, and entering one
of its directories restores the Project anchor. An external result returns one bounded snapshot to a
virtual Editor tab in the current Session; its real path and content are never durable, and Session
persistence strips the tab itself, along with any Markdown preview of it. It never creates or reuses a
Project or creates another Session.

Main registers every external snapshot it reads under the opaque `documentId` in the tab path, for the
Desktop process lifetime (bounded, oldest first). That registry is the whole authority of the
`externalDocument.*` methods: the Renderer names only an ID Main issued after the user opened that file,
never a path. `externalDocument.write` reauthorizes the path on every save (same parent directory, a
regular file, no symbolic link, a single hard link), opens it with `O_NOFOLLOW`, checks the descriptor
against the authorized inode, and overwrites it in place. In-place overwrite keeps the inode, mode,
ownership, and extended attributes of a file Caxri does not own, at the cost of atomicity: a crash
mid-save can leave it truncated, as with any in-place editor save (`IT-external-document-in-place-save`
in [the debt ledger](../../../../docs/architecture-debt.md)). The file's own inode is deliberately not pinned
across saves, because editors that save by renaming a temporary file replace it; the opened path is the
document identity, as for a Project file. Reveal in Finder and Open with Default App resolve the same
way. Open in Terminal calls the Main-only `terminal.createInExternalDirectory`, which admits that one
Main-vouched folder as a Terminal cwd; Renderer-supplied `terminal.create` cwds still stay inside the
Session's roots. Main watches each open external document's folder (rename-over saves never reach a
watch on the file) and reports a document only when its size or modification time differs from what
Main last read or wrote; a write in flight reads as busy and is checked again after it settles. The
Renderer then re-reads it under the same disk-wins rule as a Project file. Disk wins without a
conflict dialog (ADR 0013), so a newer disk state that replaces an unsaved buffer raises a
persistent warning toast naming the loss (`Your unsaved changes to <file> were replaced by changes
on disk.`) with **Restore My Changes**: the replaced text is kept in a bounded, Renderer-memory-only
stash (`discarded-buffers.ts`, at most 20 buffers) and the action puts it back as an unsaved buffer
over the new disk version. The toast's follow-up carries only paths, never a document body.

Create, rename, and move use a durable Server Core operation ID and journal under Electron user data. Each new record captures the originating Workbench Project before crossing an asynchronous boundary. A journal record without that field fails schema validation: initialization is refused with an error telling the operator to delete the journal, file mutations are rejected before touching user files, and the journal file is left in place. A `pre_stage` record may time out or cancel before any file-system mutation; once the final path and source identity checks persist a `staged` record, the native mutation continues even if Main's ordinary request deadline expires. Source and parent identities are checked again after that durable write, and create records add the newly created inode before reporting completion. Final records remain queryable until the Renderer refreshes affected file trees and reconciles root-scoped dirty buffers. Before acknowledgement removes a completed rename or move, Server Core idempotently remaps the originating Project's SQLite editor snapshot for every participating Session, including snapshots that became inactive after a root switch. Server Core restart converts abandoned pre-stage records to canceled, reconciles a staged create only against its confirmed post-create inode, and reconciles staged rename or move only when the target still has the original source inode and the source path is absent; uncertain results preserve every path and force a file-tree refresh. Per-Session execution slots remain occupied until the underlying call settles even after cancellation or acknowledgement, while retained results and pre-stage time are separately bounded. Phase logs include the operation ID, kind, Session, phase, and duration, never file contents.

An Editor save revalidates the opened replacement inode and its canonical Project containment
before writing document bytes; `O_NOFOLLOW` alone would not stop a swapped parent-directory
symlink. Failure cleanup likewise unlinks the temporary pathname only while it still resolves to
the exact inode Caxri created; an untrusted replacement is preserved rather than risking deletion
outside the Project. Node has no atomic inode-compare-and-replace or
directory-handle-relative write/unlink primitive, so an uncooperative external process can still
win the narrow temporary-path validation-to-write, cleanup-validation-to-unlink, or final target
revalidation-to-rename race. The rename replaces a late symlink itself rather than following it;
these narrow pathname races are the same explicit Node-only local filesystem tradeoff as create,
rename, move, Trash, and PTY cwd launch.

External workspace-link targets use a separate shared-`WatchHub` metadata poller even when the Project's native watcher is healthy. Reads and listings register only Server-authorized workspace entries; each tick re-resolves those entries and shares metadata reads across aliases of the same physical target. File metadata detects edits and atomic replacement, while directory metadata invalidates membership after additions or deletions. The observer never enumerates an external tree or follows undiscovered links. It maps notifications back to workspace identities and invalidates pending work on every Session or Workbench Root change, including sibling Sessions sharing one Project, and on shutdown. Direct physical outside paths gain no authority.

The external-link observer uses one 750 ms poller and at most 512 entry fingerprints. Exceeding this budget switches that Session to scoped overflow reconciliation until its watcher resets: existing consumers refetch current open documents and visible directory queries on each tick. This trades additional reads in an unusually large Session for bounded observer memory and avoids silently dropping an open document when historical reads exhaust the budget. Each metadata probe has a two-second wait deadline; an uncancellable timed-out request remains single-flight until it actually settles, including across Session resets. Pending entry probes are separately capped at 512 and physical target reads are shared. A failed or pending entry cannot prevent the remaining entries from being checked; failures reach the shared watcher diagnostics after the batch drains.

Dependency text documents reached through an authorized workspace `node_modules` entry are
read-only, including pnpm store hard links. Their reads retain regular-file, canonical-path,
device/inode and size validation; only the link-count rejection is waived. Ordinary document
reads, open authorization and every mutation retain their existing hard-link restrictions.
