# Provider lifecycle hooks and bridge installation

Caxri-managed Codex Terminal launches prepend `-c tui.auto_recap=false` before configured arguments for new,
resumed, and restarted conversations. In Codex 0.154, a CLI configuration override prevents implicit
shared-daemon reuse, so the local backend inherits the Terminal's `CAXRI_HOOK_*` identity and credentials.
This also disables Codex's automatic recap. Provider-owned arguments are applied at launch time, including
for existing saved settings. Cross-Session communication belongs to Caxri; managed launches do not depend
on Codex's shared-daemon messaging. An ordinary Shell's manually entered `codex` command is not rewritten.
See [Codex's daemon eligibility check](https://github.com/openai/codex/blob/rust-v0.154.0/codex-rs/tui/src/lib.rs#L988-L998).

Provider lifecycle hooks follow one generic Server Core contract: provider-local adapters define documented events, config targets, schema inspection, render, and removal, while `apps/server/src/domains/agents/hooks/` exclusively owns filesystem reads, a cross-process install lock, atomic replacements that write through a final symlink to its canonical target (preserving the link and existing permission bits, creating new files at mode `0600`, and failing closed on a dangling link, which health reports as a `conflict` naming the link rather than a retryable `error`), debounced provider-config watching with a slow polling fallback (a symlinked config is also watched at every file its link chain passes through, in that file's canonical directory, so editing, deleting, or restoring a dotfiles target reconciles like an edit to a regular file and a repointed link moves the target watch; a target whose directory is missing is not watched), bridge staging, the authenticated local socket, and health reporting. Adapters add content-free turn, subagent, attention, shell-tool, tool-batch, and completion phases; Claude binds `SubagentStart` plus `SubagentStop`, while Codex additionally binds its documented `SessionStart` to the activity-neutral `sessionIdentified` phase and its `PreCompact` / `PostCompact` pair to `compactionStarted` / `compactionFinished`. `SessionStart` covers startup, resume, clear, and compact before an ordinary prompt exists, so it refreshes exact identity/title without changing Session activity. Bash `PreToolUse` and `PostToolUse` map to `shellToolStarted` and `shellToolFinished`; Claude's documented `PostToolUseFailure` maps to `shellToolFailed`, while `PostToolBatch` reports when every parallel call in one main-Agent or subagent scope has resolved. A finished shell tool revalidates an already selected non-owner Workbench Root so deletion returns the Session to its owner. The shell phases may also carry a local, bounded classification that the Bash command directly invoked `git worktree add` plus the provider's opaque tool-use identifier. The classification is only intent, and Server Core attributes creation only through the paired Git proof described below. Compaction is a Server Core-only Terminal operation projected through the existing record refresh path: it never changes durable Session activity, attention, or unread state, and it clears on `PostCompact`, a standalone Escape accepted by the live PTY, a coordinator-routed `turnStarted`, `attentionRequested`, or `turnFinished` signal, PTY generation retirement, hook-authority loss, or a bounded five-minute timeout. Escape-prefixed editing and navigation sequences are not cancellation. The bridge extracts only opaque provider identifiers and that boolean classification from provider stdin; commands, arguments, paths, prompts, output, and transcripts are discarded before the signal crosses the bridge. Lifecycle hooks are enabled by default. Before installing or repairing a provider's file, the manager resolves that provider's configured CLI through the shared executable resolver. A missing CLI disables effective local authority while preserving requested profile intent, reports `notInstalled` with an install hint, and logs `agent_hooks.executable_missing` once per transition. Foreign hooks and comments are preserved, malformed trees and policy-disabled configs fail closed, Codex inline-hook conflicts are reported instead of merged, and removal independently preserves every newer marked schema even when another conflict is present. A packaged release and a worktree dev instance share the same global provider file and the same staged bridge path. The `--schema N` literal in the installed command is only the file's ordering token: a build repairs older owned entries once and leaves higher versions untouched. A higher version is usable only when its required bindings remain complete; otherwise health is incompatible and this build cannot repair it. The schema version each instance validates against and the socket it listens on travel only in that instance's `CAXRI_HOOK_*` Terminal launch environment, so a build whose entries were superseded keeps accepting its own signals instead of rewriting the file back. Desktop Main supplies the fixed per-user bridge root; tests omit it by default, while focused Electron coverage may opt into an isolated user-data hook root with `CAXRI_E2E_AGENT_HOOKS=1` so it cannot mutate real CLI configuration.

Claude settings hooks also run inside subagents and include the provider's opaque `agent_id`. The bridge preserves that identifier only to scope the event: Server Core tracks active children within the current Terminal launch, defers a parent `turnFinished` while any child remains, and settles the Session once the final child stops and no parent turn resumes within a 10-second grace window (Claude resumes the main turn itself right after `SubagentStop`, so the resumed turn's own `Stop` normally ends the work). Child-scoped hook activity refreshes the tracked child's liveness, so the fallback measures silence instead of total runtime; only while a parent completion is deferred, a 30-minute all-silent watchdog bounds the case where every completion hook is lost. A new parent turn cancels its predecessor's deferred completion without discarding children that can legally span turns, while Terminal generation retirement, hook-authority loss, provider switches, and Session deletion clear the aggregate exactly. A child-scoped completion cannot directly change parent Session activity or attention, rebind identity, or produce a duplicate unread/system notification.

Provider hook intent is profile-scoped while provider configuration is user-global. The shared registry preserves requested enablement even when a CLI temporarily disappears. Its union only protects against uninstalling another profile's hooks; install and repair require this profile's own enablement and a resolved CLI. Explicit disable or confirmed profile-directory removal can release the last intent under the existing cross-process lock. Newer files lacking required bindings remain untouched and report incompatible instead of Active. See [Hook installation authority](../../../../docs/hook-installation-authority.md) for health and write boundaries.

Hook turns use one coordinator interruption entry and evidence-based unknown recovery. See
[Hook turn recovery](../../../../docs/hook-turn-recovery.md) for the three-observation/two-minute
contract, proactive probes, lifecycle cleanup, and content-free expiry diagnostics.

When a bound Codex Terminal has no hook-supplied turn identity, its metadata probe falls back to the latest persisted `thread_turns` row for that exact thread. `rollout_ordinal` is the authoritative turn order when available; older stores fall back to insertion order. This recovers `running` and settled Session activity for a restored PTY that did not inherit the current hook environment without equating the long-lived Agent process with an active turn. The opaque turn ID stays inside Server Core as an activity marker: a newer durable `running` turn can release authority left by the preceding hooked completion, while permission-request authority remains intact. An exact hook-supplied turn remains the stronger selector. The initial launch metadata baseline keys on both state and turn identity, suppressing false loading from an `inProgress` row stranded by an abnormal Codex exit without hiding the next real turn, and it still prevents a historical settled row from creating unread attention. An explicit Terminal resume or validated in-terminal session rebind resets that baseline to an accepting sentinel, so the first authoritative snapshot of the resumed thread can restore `running` even when no new turn hook fires.

The staged hook command path and arguments stay stable across ordinary application upgrades so provider trust does not churn; bridge implementation upgrades happen behind that path, and the bridge reads the schema version for the invoked provider from `CAXRI_HOOK_SCHEMA_<PROVIDER>` rather than from the command. A hook process reads provider stdin only to extract bounded opaque session, turn, subagent, and tool identifiers and locally classify one bounded Bash command. It emits no prompt or response content and sends only provider, phase, schema, Terminal, PTY generation, token, those optional identifiers (each capped at 256 characters), and an optional literal `true` worktree-create intent over a mode-`0600` Unix socket. The tool identifier crosses only for that intent or for an attention request and its exact resolution; question text and answers never cross this lifecycle channel. The command, path, tool output, and remaining provider payload never cross the socket. Server Core waits at most 1.5 seconds for the forced before-topology read, while the bridge gives the complete downstream acknowledgement a two-second socket budget. A topology timeout records no pair; queue or transport delay lets the provider continue, and later attribution still requires a valid captured pair. A globally installed bridge stays silent when no live Caxri socket exists, including when a detached child inherited stale launch context; failures after reaching a live Caxri listener are reduced to fixed content-free stderr reasons. Server Core records content-free accepted, ignored, and rejected outcomes with stage and outcome-specific available fields: reason, provider, phase, Terminal, and only a boolean indicating whether session identity was present. An authenticated signal whose other fields are valid but whose phase is outside this build's closed set is ignored as `unknownPhase` rather than rejected; the bounded received token is logged separately and never used as a metric label. A missing, non-string, or overlong phase remains `invalidSignal`. Repeated accepted/ignored phases are logged once per PTY generation to bound routine hook volume. Tokens, environment values, session IDs, subagent IDs, prompts, tool arguments, tool results, responses, and transcripts never enter diagnostics. Server Core accepts a signal only when its random token, independently established provider binding, schema, Terminal, and current generation all match; inheriting a token cannot promote a Shell Terminal, and an authenticated signal for a provider the Terminal does not own is acknowledged as ignored rather than misreported as a failure. Startup removes a bounded set of same-profile socket paths whose encoded Server Core PID no longer exists. A validated attention-bearing hook phase is authoritative for Session activity/unread state until the next `turnStarted` or `turnFinished`; because Claude's `PermissionRequest` omits tool-call IDs, only a `PostToolBatch` for the same main-Agent or subagent scope may move `waiting` back to `running`, after every parallel call in that scope has resolved. Other Agent scopes cannot clear that state, and hook authority remains in force until the turn settles. Capability-detected metadata remains authoritative for title and usage; Agent session identity follows metadata until a validated signal names a different provider session (a manual in-terminal resume), which rebinds the Terminal, invalidates in-flight probes, and schedules a fresh metadata read. On an already-bound Codex Terminal, only an unscoped `SessionStart` may propose a different thread; before rebinding, Server Core must confirm both that exact persisted thread and that the current PTY foreground process holds its rollout, rejecting provider-declared child threads early when that relation is available. Turn hooks, persisted child threads, and unconfirmed root-like background threads retain lifecycle authority without replacing the durable resume identity. A probe with no identity preserves that exact binding until a new launch explicitly resets it. Exact authenticated hook identity may intentionally bind multiple Terminals to the same provider session; only heuristic discovery excludes identities claimed by another Terminal. While hook authority is established later probes cannot overwrite hook activity or clear the resume binding. Disabling a provider immediately ignores later signals in that profile; only the last disabling profile removes current/older Caxri entries globally. Existing PTYs that predate enabling may need a restart to inherit the bridge environment.

Codex `request_user_input` is a local function tool, not a `PermissionRequest`. Its exact-name
`PreToolUse` binding raises `attentionRequested`, and its `PostToolUse` binding raises
`attentionResolved`. The bridge carries only the bounded opaque `tool_use_id` for pairing. Server
Core removes only that pending request within its Agent scope and resumes the Session only after
all pending requests are resolved. An unrelated tool result, duplicate answer, or question answer
beside an outstanding permission request cannot clear waiting. Claude retains its whole-scope
`PostToolBatch` resolution. Turn settlement, interruption, and PTY retirement clear pending pairs.
The existing unread-attention policy still owns the yellow pulse: viewing and focusing the Session
acknowledges the reminder without answering the provider question.
