# Security policy

## Supported versions

Caxri is in active development. Development releases are published; only the latest release and
`main` are supported and considered for security fixes. No version currently carries a response, remediation, or
backport SLA.

## Report a vulnerability privately

Do not report a vulnerability in a public Issue, pull request, Discussion, or other public channel.
Never publish credentials, private data, source contents, Terminal output, Agent transcripts, or
sensitive exploit details as evidence.

Submit a report through
[GitHub private vulnerability reporting](https://github.com/tjx666/caxri/security/advisories/new).
Do not substitute a public Issue.

Include only the information needed to investigate:

- The affected Caxri version or commit.
- The affected component and realistic impact.
- Minimal reproduction steps or a sanitized proof of concept.
- Any known conditions required for exploitation.
- Whether the issue has already been disclosed elsewhere.

Remove credentials and unrelated personal or project data before submitting. A report may be
closed without action when it concerns only a separately installed Agent CLI or external service;
those products follow their own vendors' security policies.

## What to expect

The maintainer decides severity, remediation, disclosure timing, and whether a report is in scope.
Submitting a report does not create a response or fix deadline. Please avoid public disclosure
while the report is being evaluated.
