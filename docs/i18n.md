# Internationalization

The Desktop Renderer ships in English and Simplified Chinese. The `workbench.language` setting
(Settings › General › Language) selects one; its default, `null`, follows the system language: any
Chinese system preference renders Simplified Chinese, every other language renders English. Changing
the setting re-renders the open windows immediately, with no reload.

## Runtime

The runtime is [`@lobehub/ui`'s i18n](https://ui.lobehub.com/components/i18n), wrapped by
`apps/desktop/src/renderer/src/i18n/`, the only Renderer module allowed to import the
library (an accepted exception recorded in the stack baseline; ESLint enforces it):

- `useLocaleStore` is the single source of the active locale. `I18nProvider` renders the library's
  `ConfigProvider` with that locale and its flat dictionary. It deliberately does not use the library's `I18nProvider` export: that component
  always installs a global focus ring that overrides every focus-visible outline with `!important`.
  `ConfigProvider` owns the same i18n context and accepts `globalFocusRing: false`.
- `syncWorkbenchLocale()` (`stores/workbench-locale.ts`) subscribes to the Workbench store in the
  Workbench and Agent Commander windows and applies the setting synchronously, inside the snapshot
  write and before React renders it. A provider effect would update the store one render late, so
  `translate()` calls made during the switching render would still return the previous language.
  Process Explorer has no Workbench snapshot, so Main passes its resolved `workbench.language` locale on the window's
  entry URL (`caxri-locale`) and the window opens in the Workbench's language; it keeps that language until reopened.
- `useTranslation()` returns a typed `t(key, parameters?)` for components. It reads the library
  context, so a language change re-renders every consumer.
- `translate(key, parameters?)` serves code outside React: stores, command handlers, toasts raised
  from events. It reads `useLocaleStore`. Its
  result is a snapshot. Never call it at module top level, and never call it during render where
  `useTranslation()` is available.

Main translates its own native UI (the menu bar, message boxes, and file dialog titles) through
`apps/desktop/src/main/locale.ts`. Its dictionaries are the shared `commands` namespace plus the
Main-only `desktop` namespace in `apps/desktop/src/shared/i18n/`. Every native menu refresh reads
`workbench.language` together with the keybindings and resolves `null` against
`app.getLocale()`, Chromium's locale, which honors `--lang` like the Renderer does; `settings.changed` triggers that refresh, so the menu bar
rebuilds in the new language. Dialogs translate when they open. `translateMain()` reads module state, so the prompt builders stay plain
functions that Vitest imports without Electron.

The library's own built-in strings (`common.cancel`, `common.confirm`, `common.delete`,
`common.edit`, `common.clear`, `common.empty`, and the `form.*`, `hotkey.*`, `image.*` groups) are
merged into the same dictionaries and are valid keys. Caxri resources must not redefine them; the
i18n unit test rejects an overlap.

## Resources

`i18n/locales/en/<namespace>.ts` holds the English source strings, one module per Renderer feature
(`agent-chat.ts` exports `agentChat`), plus:

| Namespace  | Owns                                                                         |
| ---------- | ---------------------------------------------------------------------------- |
| `common`   | Generic single words reused across features (Close, Retry, Save, ...)        |
| `core`     | Shared chrome outside `features/`: `components/`, `hooks/`, `lib/`, `stores` |
| `commands` | Command titles and categories, in `apps/desktop/src/shared/i18n/`            |
| `desktop`  | Main-only native menu and dialog copy, in `apps/desktop/src/shared/i18n/`    |
| `settings` | Settings categories, rows, and the protocol settings catalog                 |

The `commands` namespace lives in `apps/desktop/src/shared/i18n/{en,zh-cn}/` because Main's native
menu shows the same titles; the Renderer aggregates import it from there.

`i18n/locales/zh-cn/<namespace>.ts` mirrors each module and is typed
`TranslatedNamespace<typeof source>`, so a missing, extra, or misspelled key fails type checking.
The unit test additionally checks that every translation is non-empty and keeps the same
`{{placeholders}}` as its English source.

Keys are flat strings, `<namespace>.<camelCase path>`, for example
`agentChat.composer.placeholder`. Choose keys by meaning, not by English wording, so a copy edit does
not force a rename. Placeholders use `{{name}}`. There is no plural engine: choose between `...One` and
`...Other` keys in code when English needs different forms (Chinese can repeat the same text).

### Strings owned by the protocol catalogs

The command catalog and the settings catalog in `@caxri/protocol` keep their English `title`,
`description`, and option labels. They remain the source of search keywords, the CLI, and the
native menu. The Renderer translates them at display time through keys derived from the stable id,
such as `` `commands.${id}` `` or `` `settings.${key}.title` ``. A template literal over the id union
type-checks against `TranslationKey` only when every id has an entry, so a new command or setting
fails type checking until it is translated.

Some presentation helpers in `@caxri/protocol` produce English copy for the phone and the CLI
(Agent Chat activity, tool and work labels, turn labels, tracker and edited-file titles, Commander
Inbox labels, Git diff tab labels, request copy), and Desktop renders a localized counterpart that
rebuilds the same text from translation keys. Under the English locale both must agree byte for
byte. Every such Desktop counterpart registers a row in
`apps/desktop/src/renderer/src/i18n/__tests__/english-counterpart-parity.test.ts`, which feeds both
sides inputs that reach every branch and enum member, so a wording or rule change on one side fails
there instead of silently diverging.

The placeholder title of an unnamed Session (`DEFAULT_SESSION_TITLE`, `Untitled`) is Server data shared with the CLI and
mobile, so it stays English in storage. Renderer surfaces show it through `sessionTitleForDisplay`
(`features/session/session-title.ts`); matching, sorting, and rename requests keep the stored title.

## What stays untranslated

- Product and vendor names: Caxri, Claude, Codex, Grok, GitHub, macOS.
- Identifiers the user types or matches: command ids, setting keys, file paths, Git refs, shell
  commands, keyboard shortcut glyphs.
- Agent prompts, Agent transcripts, Terminal output, log and diagnostic text, and anything sent to
  the Server or an Agent.
- Text inside tests and E2E selectors. E2E launches pass Chromium `--lang=en-US`, so the default
  `workbench.language` resolves to English on any host.

Suspend is the automatic memory-saving park of a background Agent (and the Process Explorer action that does the
same by hand); it is never rendered as Pause or 暂停, which belong to progress and recovery states. Copy that points
at a setting builds its `Settings › Category` path from the category's translation (`settingCategoryPath`) rather than
spelling it by hand.

Follow macOS and VS Code Simplified Chinese conventions for everything else: full-width
punctuation (`，。：？！（）`) inside Chinese sentences, a space between Chinese and adjacent Latin
words or numbers, and `…` for an ellipsis.
