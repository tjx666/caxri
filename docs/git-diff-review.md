# Git diff review comments

Desktop Git diff tabs support Session-scoped comments on either comparison side. Each anchor is isolated by diff source (working tree, pull request, or commit SHA) and file path. Binary and patch-only views do not offer line comments because their display rows are not source-file line numbers. In a single-file or Open Changes diff, hover a line's gutter and click `+`, select lines and use **Add Review Comment** from the editor context menu or Command Palette, or press `Cmd+Shift+M`. The card under the selected line accepts `Cmd+Enter` to save and `Escape` to cancel. Comments can be edited or deleted in place.

The diff tab badge and toolbar count pending comments for the current repository. **Send N comments to Agent** previews one prompt containing each file reference, diff source, comparison side, captured code snippet, and comment. The target is the running Agent Terminal selected by the same visible-then-recent Session rule as file references. The Terminal receives the prompt as one bracketed paste and a submit key. Large prompts use the existing local long-paste file route. A review send requires a managed Agent launch and is rejected if that launch has exited, so it cannot submit into the shell. A failed send keeps all comments pending. A successful send marks them sent and excludes them from later sends.

Comments live in the Renderer for the lifetime of the app. They do not survive a full restart. Each anchor records its original line span and snippet. When refreshed diff content no longer matches that span, a pending comment becomes **outdated** and is excluded from sending; it is never moved to another line automatically. The toolbar can clear sent and outdated cards. Comment cards remain visible when a multi-file row is virtualized out of view and then mounted again.

`git-review-comments.ts` owns state, anchor comparison, prompt serialization, and Terminal paste formatting. `git-review-comment-binding.ts` mounts Monaco view zones for both sides and the single-sided added/deleted editor. `git-review-send-commands.ts` owns Terminal selection and the typed input boundary. The existing `terminal.input` method accepts a managed-Agent guard for review submissions; no SQLite schema is involved.
